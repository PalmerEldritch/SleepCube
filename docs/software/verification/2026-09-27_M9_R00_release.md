# M9 R00 Release Verification

**Date:** 2026-09-27

**Status:** PASS

## Scope

M9 promotes the M8-validated software baseline, including the passed
`R00-DUR-001` 60-minute default regression, to the R00 release. It does not add
product behavior. The release gate covers final document/ADR consistency,
removal of the superseded Control-local audio backend from the active source
and build graph, reproducible product builds, a final integrated target smoke
test, and an annotated release tag.

## Baseline audit

- All 55 SRS, 24 UX and 29 ICD IDs retain the complete M8 traceability and
  passing evidence recorded in the VVM.
- The accepted architecture decisions are ADR-0002 through ADR-0008.
  ADR-0001 remains superseded and archived under `docs/legacy/adr/`.
- No unresolved R00-critical behavioral TBD was found.
- `AUD-ISS-001` remains an evidence-backed, accepted low-level R00 limitation;
  it is not claimed resolved by this release activity.
- Historical milestone reports and their earlier 30-minute build identities
  remain unchanged because they describe the images actually tested.

## Release-path cleanup

The obsolete Waveshare-local storage/decoder/player/I2S implementation and its
diagnostic sources were removed from `firmware/control/main/`. The corresponding
Kconfig switches, component requirements, Helix MP3 dependency and Control
SPIFFS image generation were removed. Control `audio_service` now has one R00
implementation: the bounded semantic facade to the Audio Controller.

The custom Control partition table is retained to avoid an unnecessary flash
layout migration. Its legacy storage partition is unused: the R00 Control build
does not create, flash or mount a SPIFFS image.

`firmware/control/sdkconfig.r00.defaults` is the explicit release overlay. It
selects the ESP32-C6 8 MB/USB Serial-JTAG product configuration, 3,600-second
session requests, product UI/lighting and the validated LED floors, with the
semantic console and timing trace disabled.

Both ESP-IDF projects explicitly identify their application version as `R00`.
This prevents a documentation-only commit after candidate validation from
silently changing the embedded version string and binary hashes.

## Integrated target smoke

Stable USB identities were resolved before flashing:

- Control `AC:EB:E6:1E:67:C4` on `/dev/ttyACM0`;
- Audio `44:1B:F6:F4:FE:C8` on `/dev/ttyACM1`.

Both exact product images flashed with all write hashes verified. After the
Atom was manually returned from download mode, repeated Control status probes
reported synchronized `STOPPED`, persisted volume 59%, `remaining=0`, and
`fault=0`. The speaker was silent and the user reported no abnormal display or
LED-strip behavior.

A product tap issued `PLAY(3600s)`. Audio established its local 3,600-second
deadline before entering `PLAYING`; both controllers reported the matching
countdown at 59% and `fault=0`. A second tap issued STOP. Audio logged the
one-second remote-stop fade and reached `STOPPED`, manual reason 1,
`remaining=0`; repeated Control probes remained `STOPPED`, `fault=0`, without
restart. The user confirmed the audio/visual response was clean and all
observations were normal.

The full hour was not repeated for M9: M8-END-001 already exercises the same
3,600-second distributed runtime/deadline path, while this smoke verifies the
exact R00 binaries and release configuration.

## Exit disposition

PASS. All M9 deliverables and the R00 release gate are satisfied. The active
documents are promoted to R00 and the annotated release tag is `software-r00`.
`AUD-ISS-001` remains the documented accepted limitation and post-R00 audio-
quality improvement; this release does not claim its physical cause resolved.
